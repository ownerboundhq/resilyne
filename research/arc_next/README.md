# Arc Next — original language-model research

Arc's previous 170,725-parameter word-level model is preserved. This is a new architecture initialized from random weights, not a continuation of the incompatible old checkpoint. The default configuration is 4 decoder layers, width 256, 4 heads, 128-token context, a 4,096-piece SentencePiece BPE tokenizer with byte fallback, and tied embedding/output weights (about 4.24 million parameters). No external pretrained weights are loaded.

## Data

- HuggingFaceTB/cosmopedia: Apache-2.0, synthetic educational prose generated by Mixtral; three bounded source subsets. https://huggingface.co/datasets/HuggingFaceTB/cosmopedia
- OpenAssistant/oasst1: Apache-2.0, human conversations; English, filtered by review/rank/labels, separate official validation split. https://huggingface.co/datasets/OpenAssistant/oasst1
- The prepare script records the resolved dataset revision, dataset file hashes and counts. Training text is not committed to the public repository. The corpus requires further quality, rights and safety review before commercial use; automatic PII and quality filtering is incomplete. Attribution does not guarantee every example is safe or accurate.

## Run on your own compute

Install PyTorch (CPU or CUDA), datasets==3.6.0, sentencepiece==0.2.1, and huggingface_hub==0.32.4.

```sh
python research/arc_next/prepare.py --docs 10000
python research/arc_next/train.py --pre-steps 1500 --chat-steps 500 --seconds 660
```

For GPU experiments increase token budget on your own compute. To resume, reuse the original data, tokenizer and output directory and pass --resume research/arc_next/run/checkpoint.pt. Resume adds new steps in both stages; set --pre-steps 0 or --chat-steps 0 to skip a stage's updates.

The one-off GitHub workflow runs a bounded research smoke experiment and preserves a model checkpoint, tokenizer, measured held-out loss and raw generated sample responses as run artifacts. It never replaces the public model. Lower perplexity is not evidence of correct answers; independent factual, arithmetic, dialogue, privacy and safety evaluation and browser-runtime implementation are required before promoting any successor. The default Arc remains unchanged.

## Million-token continuation

The bounded continuation targets cumulative 5,000,000 supervised pretraining token positions and 300,000 supervised assistant-response token positions. These are processed positions (including repeat exposure), not unique vocabulary entries or millions of distinct documents. The first successful experiment's checkpoint, optimizer and tokenizer are reused; the original corpus is reconstructed with pinned revisions and matching hashes. The report records actual counts and whether each target was reached. The CPU time cap can stop training before the targets; larger campaigns should run on dedicated compute. No automatic promotion to the public website.

For subsequent local continuation, use the same corpus and output directory, then run:

```sh
python research/arc_next/train.py --resume research/arc_next/run/checkpoint.pt --pre-steps 6000 --chat-steps 1500 --seconds 1800 --pre-token-target 5000000 --chat-token-target 300000
```

## Local inference and unfamiliar-question evaluation

```sh
python research/arc_next/inference.py research/arc_next/run/checkpoint.pt
python research/arc_next/evaluate_generalization.py research/arc_next/run/checkpoint.pt --n 20 --out generalization.json
```

The second command generates novel random names, context associations, operand combinations, and output instructions after training. It stores the seed, exact responses, checkpoint SHA-256 and per-category scores. Do not train on evaluation cases or tune a release to them; keep a separate final set and perform factual and safety review. The supplied assistant acknowledgement in memory tests is not a generated response. The new conversation packing keeps room for the user's question and does not teach a false stop token for truncated answers. Validation loss before/after a packing change is not directly comparable across versions. No claim of general-purpose ability is made until actual results exist.

## Post-pretraining conversation alignment (dedicated compute)

The first continuation used a cumulative assistant-token target of 300,000, already exceeded by the original checkpoint. Its actual chat update count must be checked before judging conversational quality. The trainer now accepts `--chat-extra-tokens`, an additional budget independent of prior training. Run the following after downloading the successful continuation artifact, retaining its tokenizer and restoring the exact recorded corpus. This is a proposed local/dedicated-compute experiment, not an automatically scheduled GitHub training job.

```sh
python research/arc_next/train.py --resume research/arc_next/run/checkpoint.pt --pre-steps 0 --chat-steps 6000 --chat-extra-tokens 500000 --seconds 3600
python research/arc_next/evaluate_generalization.py research/arc_next/run/checkpoint.pt --n 20 --out generalization.json
```

The wall-clock and step caps can stop before the target. Record actual additional tokens, run qualitative checks, and use fresh evaluation examples rather than training on the previous challenge suite. Preserve the prior artifact before resuming. No automatic promotion or additional hosted compute allocation is implied.
